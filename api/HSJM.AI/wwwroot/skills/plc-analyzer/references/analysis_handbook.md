# PLC程序LLM分析手册

## 概述

本手册指导LLM如何分析PLC程序的结构化提取结果，理解程序逻辑并生成有价值的解读。

---

## 第一部分：块类型识别与功能推断

### 1.1 西门子TIA Portal块类型

| 块类型 | 全称 | 功能描述 | 典型应用 |
|--------|------|----------|----------|
| **FB** | Function Block | 功能块，有实例数据，可保持状态 | 电机控制、阀门控制、PID控制 |
| **FC** | Function | 函数，无实例数据，纯计算逻辑 | 数据转换、公式计算、通用算法 |
| **DB** | Data Block | 数据块，存储结构化数据 | 配方数据、参数存储、状态记录 |
| **GlobalDB** | Global Data Block | 全局数据块 | 系统参数、共享数据 |
| **InstanceDB** | Instance Data Block | 实例数据块，FB的数据存储 | FB运行时数据 |
| **OB** | Organization Block | 组织块，系统调用入口 | 主程序、中断处理、故障处理 |

### 1.2 编程语言特点

| 语言 | 适用场景 | 分析要点 |
|------|----------|----------|
| **LAD** | 梯形图，直观的继电器逻辑 | 关注触点串并联、线圈输出 |
| **FBD** | 功能块图，数据流导向 | 关注功能块连接、数据流向 |
| **SCL** | 结构化文本，高级语言 | 关注IF/CASE/FOR逻辑、表达式 |
| **STL** | 语句表，底层指令 | 关注累加器操作、跳转逻辑 |
| **GRAPH** | 顺序功能图，步序控制 | 关注步-转换-动作结构 |

### 1.3 块命名约定解读

**常见命名模式：**

```
FB{编号}_{功能描述}
例: FB112_StationControl → 工位控制功能块

FC{编号}_{功能描述}  
例: FC_Safety → 安全相关函数

DB{编号}_{数据描述}
例: DB20_SafeControl → 安全控制数据块

OB{编号}
例: OB1 → 主循环, OB100 → 启动, OB82 → 诊断中断
```

**编号约定（常见）：**
- 1-99: 基础/系统块
- 100-999: 工位/设备控制
- 1000-9999: 特殊功能/库
- 3000+: 标准库功能块

## 第二部分：变量分析指南

### 2.1 作用域解读

| 作用域 | 含义 | 分析优先级 |
|--------|------|------------|
| **IN** | 输入参数，调用时传入 | ⭐⭐⭐ 最高 |
| **OUT** | 输出参数，返回结果 | ⭐⭐⭐ 最高 |
| **INOUT** | 双向参数，输入并修改 | ⭐⭐⭐ 高 |
| **STAT** | 静态变量，保持值 | ⭐⭐ 中 |
| **TEMP** | 临时变量，仅本次调用有效 | ⭐ 低 |
| **CONST** | 常量，不可修改 | ⭐ 参考 |

### 2.2 命名前缀约定

**输入/输出信号：**
```
i_   / I_   → 输入信号 (Input)
o_   / O_   → 输出信号 (Output)  
q_   / Q_   → 输出信号 (德语风格 Quit/Output)
io_  / IO_  → 双向信号
```

**数据类型提示：**
```
b_   / B_   → Bool 布尔
n_   / N_   → Int/Number 整数
r_   / R_   → Real 实数
s_   / S_   → String 字符串
t_   / T_   → Time 时间
dt_  / DT_  → DateTime 日期时间
arr_ / A_   → Array 数组
```

**功能提示：**
```
_Cmd      → Command 命令
_Fbk      → Feedback 反馈
_Sts      → Status 状态
_Alm      → Alarm 报警
_Set      → Setpoint 设定值
_Act      → Actual 实际值
_Req      → Request 请求
_Ack      → Acknowledge 确认
_Rdy      → Ready 就绪
_Err      → Error 错误
_En       → Enable 使能
_Dis      → Disable 禁用
```

**设备类型提示：**
```
Motor_    → 电机
Valve_    → 阀门
Cylinder_ → 气缸
Sensor_   → 传感器
VFD_      → 变频器
Servo_    → 伺服
Robot_    → 机器人
```

### 2.3 常见数据类型解读

| 类型 | 含义 | 典型用途 |
|------|------|----------|
| Bool | 布尔 | 开关量、状态位 |
| Int | 16位整数 | 计数、索引、枚举 |
| DInt | 32位整数 | 大数值、编码器值 |
| Real | 32位浮点 | 模拟量、PID参数 |
| Time | 时间间隔 | 定时器设定 |

| Array[...] of X | X类型数组 | 批量数据 |

| "UDT_xxx" | 用户定义类型 | 标准化数据结构 |

## 第三部分：调用关系分析

### 3.1 调用层次解读

```
OB1 (主循环)
├── FB100_System (系统控制)
│   ├── FC_Safety (安全检查)
│   └── FC_Comm (通信处理)
├── FB110_Station1 (工位1)
│   ├── FB3001_Motor (电机控制实例)
│   └── FB3002_Valve (阀门控制实例)
└── FB120_Station2 (工位2)
    └── ...
```

### 3.2 常见调用模式

**模式1：设备控制封装**
```
工位FB → 调用多个设备FB实例
例: FB112_StationControl → FB3001_Motor[1..4]
```

**模式2：功能库调用**
```
应用FB → 调用标准库FC/FB
例: FB_Process → FC_PID, FC_Scale, FC_Limit
```

**模式3：安全链调用**
```
安全OB → 安全FB → 安全FC
例: OB_Safety → FB_EStop → FC_SafetyCheck
```

## 第四部分：GRAPH顺控分析

### 4.1 GRAPH程序结构

```
GRAPH程序 = 步(Step) + 转换(Transition) + 动作(Action)

[Step 1: 初始化]
    ↓ (转换条件: 启动信号)
[Step 2: 准备]
    ↓ (转换条件: 准备完成)
[Step 3: 执行]
    ↓ (转换条件: 执行完成)
[Step 4: 结束]
    ↓ (转换条件: 复位)
[返回Step 1]
```

### 4.2 步(Step)分析

**步的属性：**
- `Number`: 步号，执行顺序标识
- `Name`: 步名称，描述当前阶段
- `InitStep`: 是否为初始步（程序入口）
- `MaximumTime`: 最大允许时间（超时报警）
- `WarningTime`: 警告时间

**动作限定符：**
| 限定符 | 含义 | 说明 |
|--------|------|------|
| N | Non-stored | 步活动时执行，离开时停止 |
| S | Set | 步活动时置位，保持 |
| R | Reset | 步活动时复位 |
| D | Delayed | 延时后执行 |
| L | Limited | 限时执行 |
| P | Pulse | 脉冲执行一次 |

### 4.3 转换(Transition)分析

转换条件决定何时从一个步跳转到下一个步：

**常见转换条件模式：**
```
1. 传感器信号: i_SensorReached AND i_SafetyOK
2. 定时完成: Step.T >= T#5s
3. 动作完成: o_CylinderExtend AND i_CylinderPos
4. 手动确认: i_OperatorConfirm
5. 无条件: TRUE (自动跳转)
```

### 4.4 GRAPH分析模板

```
【GRAPH程序分析】
程序名: {name}
总步数: {step_count}
初始步: {init_step}

【流程概述】
{逐步描述每个步骤的功能和转换条件}

【关键控制点】
- 启动条件: ...
- 停止条件: ...
- 异常处理: ...

【时序要求】
- Step X 最大时间: ...
- 整体循环时间: ...
```

## 第五部分：故障诊断辅助

### 5.1 常见故障模式

**模式1：超时故障**
```
现象: GRAPH步卡住不前进
排查: 检查转换条件中的传感器信号
关注变量: i_xxx, Sensor_xxx
```

**模式2：互锁故障**
```
现象: 动作无法执行
排查: 检查安全互锁条件
关注变量: Safety_OK, Enable, Interlock
```

**模式3：通信故障**
```
现象: 数据不更新
排查: 检查通信状态位
关注变量: Comm_OK, Error, Timeout
```

**模式4：状态机卡死**
```
现象: 状态不切换
排查: 检查状态变量和切换条件
关注变量: State, Mode, Step, Phase
```

### 5.2 诊断分析模板

```
【故障诊断分析】

故障现象: {用户描述}

相关程序块:
- {block_name}: {block_function}

可疑变量:
- {var_path}: 当前值={value}, 预期={expected}

排查建议:
1. 检查 {var1} 的输入信号来源
2. 确认 {var2} 的互锁条件
3. 查看 {var3} 的历史趋势

可能原因:
- 原因A: ...
- 原因B: ...
```
